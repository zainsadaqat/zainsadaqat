<details>
<summary><b>What a Lesson With Me Looks Like</b></summary>

<br>

A typical lesson is not:

> "Watch me code for an hour."

Instead, we work through a cycle like this:

```text
Concept
   │
   ▼
Simple Example
   │
   ▼
Predict What Happens
   │
   ▼
Write It Yourself
   │
   ▼
Break the Code
   │
   ▼
Debug It
   │
   ▼
Solve a New Problem
   │
   ▼
Apply It to a Project
```

The difficulty changes according to the student.

A beginner might be learning why a loop repeats.

An exam student might dry-run an algorithm.

A developer might be reasoning about database relationships, APIs, authentication, async code, or application architecture.

</details>

## A Few Things I Care About

```text
Understanding > memorization
Practice      > passive watching
Clarity       > jargon
Fundamentals  > shortcuts
Consistency   > intensity
Building      > endless tutorials
```

Good programmers are not people who remember every function.

They are people who can **break a problem down, reason about it, test assumptions, find information, debug mistakes, and keep moving.**

That is the skill I try to teach.
